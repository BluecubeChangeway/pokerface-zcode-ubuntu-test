## 二、工程准备思考（我方要提前备好的）

### 1. 独立界面（工作区）壳层结构
"数据清洗 / 卡牌画布 / 绩效核算 / 数据导出 = 独立界面切换显示"意味着需要一个**界面（工作区）级壳层**。
我的设计前提（供 UI 阶段与用户确认）：**工作区切换是纯表现层结构**——业务事实（Relation / Result / 模型）
不因切换界面而变化，四个界面只是同一事实世界的四个取景窗口（数据清洗偏表格形态=AGENTS §16、
画布偏空间形态、核算偏计算/结果形态、导出偏输出形态）。
准备动作（进入 UI 前可做的工程骨架，非视觉设计）：无——当前竖切片单界面，壳层结构属 UI IMPLEMENTATION
阶段工作，提前做有过度工程风险；**本项准备 = 本文件登记 + 设计时提供"当前系统可支撑的四个界面各自的
数据就绪度"评估**（见 §三）。

### 2. 多语言（i18n）技术准备
当前竖切片与运行时面板文案硬编码中文。进入 UI 阶段时：文案抽离为键值（i18n 资源文件），
组件引用键。**准备动作**：登记即可——抽离随 UI IMPLEMENTATION 一起做（提前抽离无收益）。
需用户届时回答：支持哪些语言；医学术语表（DOMAIN_GLOSSARY）是否需要双语对照版本。

### 3. 多主题（Skin 系统）技术准备
D-057（视觉 Skin ≠ 业务类型）/ D-058（V1 为 Skin 系统预留架构边界）已封板。
**准备动作**：Design tokens 工程化方案（契约 §3-C：token 文件结构 / 主题接入 / 切换机制）
可在 DESIGN HANDOFF 后、UI IMPLEMENTATION 中由我实施；token 内容必须来自设计侧。
CSS 变量层与领域层的隔离已在架构上成立（表现层不反向决定业务语义，AGENTS §18）。

### 4. "UI 新功能 → 对接点新增 + 后台功能增加"联动机制（用户 U-UI-6）
既定纪律已天然覆盖：任何新 UI 功能 = 新接线层入口（或扩展既有入口）→ 经服务层 → 领域层，
先裁定语义（两级协议）再写码，测试守护（AGENTS §4/§29、03-PARALLEL-RULES §3）。
**准备动作**：维护"当前接线点清单"（下表），UI 阶段每新增一个界面功能就对照登记
"界面元素 → 接线点 → 服务 → 领域语义来源"，保证可追溯、不遗漏后台配套。

**当前运行时接线点清单（UI IMPLEMENTATION 的对接基础）**：

## 三、进入 UI 阶段的门槛判定（我的承诺）
